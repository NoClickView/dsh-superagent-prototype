# 05: 线索唤起使用可恢复额度并持续可用

**What to build:** 实验体持续运行并经历多轮对话后，新的强相关线索仍能自动唤起旧经历；通过有界、可补充的额度控制短期打扰，而不是累计八次后永久停止。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent
**Labels:** ready-for-agent
**Priority:** P2
**Spec:** [长期记忆规格](https://github.com/NoClickView/dsh-superagent-prototype/blob/f5b6a3270f390a8068413fdb61f6d2757c020a30/.scratch/long-term-memory/spec.md)
**Source:** 2026-11-07 实现审查；基线 da65294 至 bcf5ea6。

审查复现：连续 12 次强关联输入且上下文有足够空间时，通知累计为 0、1、2、3、4、5、6、7、8、8、8、8；计数没有进程内恢复条件，重启前所有后续线索均被忽略。

- [ ] 以明确记录、可配置的时间窗或轮次策略补充唤起额度；额度耗尽后的恢复不依赖进程重启，不要求实验体主动管理记忆。
- [ ] 额度恢复后，全新强相关线索仍能唤起符合范围的旧经历；弱线索不唤起，已遗忘经历仍可按既有阈值重新成为候选。
- [ ] 对同一未变化经历进行有界去重，并明确再次可唤起的条件；去重状态自身有容量或保留期限，不能随多年运行无限增长。
- [ ] 每次通知仍受完整请求预算约束并优先呈现梗概；额度补充不提高记忆重要性、证据可信度，不重置事件年龄或延长原文保留期。
- [ ] 明确额度补充、实际交付成功、失败重试及重启时的计数语义，不重复投递、不因重试制造额度或永久占用额度。
- [ ] 在 Runtime 集成测试中覆盖超过八次成功唤起、额度耗尽、可控时间或轮次推进后恢复、不同线索、重复经历、预算不足及重启；直接检查模型可见通知与记忆状态。
- [ ] 通过现有状态或诊断记录说明未唤起是额度不足、重复、相关性不足还是上下文无空间，不新增独立管理产品。

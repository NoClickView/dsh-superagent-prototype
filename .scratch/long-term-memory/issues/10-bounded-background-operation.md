# 10: 后台积压或规则升级时持续服务

**What to build:** 后台慢、离线或原则版本变化时，前台继续使用一致快照和有界新事件；后台按有限额度逐步恢复，操作者可以看到积压、成本与处理进度。

**Blocked by:** 09 — 容量受限时淘汰原文并保持可回忆

**Status:** ready-for-agent

**Spec:** [长期记忆规格](https://github.com/NoClickView/dsh-superagent-prototype/blob/f5b6a3270f390a8068413fdb61f6d2757c020a30/.scratch/long-term-memory/spec.md)

- [ ] 为模型调用、并发、批次、待处理材料与重试设置可计量上限，不每天重新评分或总结全部历史。
- [ ] 后台暂停或长时间超时时，前台用已发布版本与有界新事件继续服务；不丢失已接收经历，不靠无限队列或无限输入缓冲。
- [ ] 存储/队列容量满时按已有容量合同背压；清晰区分已接收、待处理、失败和暂未接收材料。
- [ ] 原则或模型版本改变后，用有限增量作业重评受影响记忆；重试和旧版本输出不重复生效、不覆盖当前材料。
- [ ] 通过现有运行状态或只读资源公开积压、版本、最近错误、预算使用与处理进度，不引入独立可视化产品。
- [ ] 输入中的指令性文本不改变原则或预算；后台控制状态由运行时明确保存，而不是评估器长期对话。
- [ ] Runtime 集成测试同时施加事件持续输入、后台中断、恢复、升级及容量压力，所有实际模型请求始终守住预算。

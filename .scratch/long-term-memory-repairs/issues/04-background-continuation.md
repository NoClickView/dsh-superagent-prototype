# 04: 后台积压按有限额度自动续跑

**What to build:** 后台恢复或接收一批经历后，在没有新事件、没有操作者主动调用的情况下，自动逐轮处理剩余作业；每轮保持调用、批次和并发上限，暂停或容量不足时停止空转。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent
**Labels:** ready-for-agent
**Priority:** P2
**Spec:** [长期记忆规格](https://github.com/NoClickView/dsh-superagent-prototype/blob/f5b6a3270f390a8068413fdb61f6d2757c020a30/.scratch/long-term-memory/spec.md)
**Source:** 2026-11-07 实现审查；基线 da65294 至 bcf5ea6。包含 P3 窄依赖规范问题的先行整理。

审查复现：暂停期间排入 6 个作业，每轮调用上限设为 2；恢复后只运行 2 个，剩余 4 个一直等待。显式调用等待清空接口才会驱动其继续执行。

- [ ] 先缩小后台调度器的服务依赖，只暴露它实际需要的版本、策略、状态、扫描与回收能力；保留作业候选通过记忆服务提交的既有职责。
- [ ] 单轮达到额度而仍有可推进工作时，自动安排下一轮并让出执行机会；只有一个调度者，不依赖新增事件或测试等待函数驱动进度。
- [ ] 每轮调用数、总处理批次、并发、等待队列和重试均遵守有效配置；持续积压时前台仍可响应，失败不得变成无上限重试。
- [ ] 暂停、容量不足或没有可推进工作时不忙循环；恢复、容量释放和可重试条件变化后有明确的再次调度入口。
- [ ] Runtime 停止时取消后续调度，不在关闭存储后继续提交；重新启动仍按已有幂等与基础版本规则处理工作。
- [ ] 在 Runtime 集成测试中用可控时钟、模型响应和只读进度观察，验证 6 个作业按每轮 2 个自动完成；不得调用会主动清空队列的等待接口来证明自动续跑。
- [ ] 覆盖运行中追加、暂停再恢复、容量不足再恢复、模型超时及重复唤醒；现有健康状态准确显示推进或阻塞原因。

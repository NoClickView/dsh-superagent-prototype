# 02: 压缩和标题生成也遵守模型输入上限

**What to build:** 会话历史超限时，系统使用有界步骤恢复可继续运行的上下文；压缩和标题生成始终遵守与普通调用相同的输入预算，不能通过请求用途获得超额发送资格。

**Blocked by:** 01 — 最终模型请求计入历史工具定义并守住预算。

**Status:** ready-for-agent
**Labels:** ready-for-agent
**Priority:** P1
**Spec:** [长期记忆规格](https://github.com/NoClickView/dsh-superagent-prototype/blob/f5b6a3270f390a8068413fdb61f6d2757c020a30/.scratch/long-term-memory/spec.md)
**Source:** 2026-11-07 实现审查；基线 da65294 至 bcf5ea6。

审查复现：预算为 800 字符时，9,000 字符的普通请求被暂停，同一输入以压缩或标题生成为用途时却被作为恢复请求放行。

- [ ] 复用 01 单的完整请求校验，取消压缩和标题用途的超限放行，包括无效预算配置；所有真正发出的请求都守住配置上限。
- [ ] 超大历史通过每步均有界的压缩或分段处理恢复；小型必要输入也无法容纳时显式暂停并报告原因，不以绕过上限来解除暂停。
- [ ] 维持现行授权、活动任务与工具调用关联；压缩失败、中断或重试不破坏可恢复历史，不重复提交压缩成果。
- [ ] 标题生成只使用预算内材料，无法生成时可解释地延后或跳过，不阻塞正常业务和会话恢复。
- [ ] 在 Runtime 集成测试中，从超限历史进入实际恢复流程并继续普通请求；不能靠测试直接清空历史或只修改用途来模拟恢复成功。
- [ ] 对压缩的每个子请求、标题请求、普通重试及后台请求检查最终适配器输入；覆盖超限、边界、不可用配置、恢复中断和后台暂停。
- [ ] 可观测状态区分恢复中、恢复完成及无法恢复的暂停；不得将超限发送记作成功恢复。

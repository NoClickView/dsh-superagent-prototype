# 03: 用实际权限保证外部只读

**What to build:** 在声明支持的部署环境里，实验体及其他消费者能够读取已发布记忆，但即使通过文件或 shell 工具，也不能绕过记忆服务修改权威记录。

**Blocked by:** 02 — 经历写入后可跨重启召回

**Status:** ready-for-agent

**Spec:** [长期记忆规格](https://github.com/NoClickView/dsh-superagent-prototype/blob/f5b6a3270f390a8068413fdb61f6d2757c020a30/.scratch/long-term-memory/spec.md)

- [ ] 基于实际部署支持的账户、进程或沙箱边界分离唯一写入者与读者权限；不能仅依赖模块封装、提示词或文件约定。
- [ ] 贯通部署配置、启动检查、正常事件写入、读取和拒绝绕过写入的可见结果；不扩展其他工作区权限。
- [ ] 用受限进程或账户验证直接写入、替换和删除权威记录失败，正常通过服务上报事件仍成功。
- [ ] 检查适用环境下目录继承、可写父目录及链接绕过等实际边界；记录验证过的部署条件，不声称已有跨平台保证。
- [ ] 无法建立所需隔离时拒绝启用长期记忆写入，并在现有运行状态渠道说明原因。
- [ ] 测试仅断言文件保持完整、服务结果和权限拒绝，不锁定内部类或调用次数。

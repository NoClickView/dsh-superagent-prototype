# 长期记忆：有界上下文、文件持久化与无状态后台整理

Status: ready-for-agent
Labels: ready-for-agent
Created: 2026-11-06
Scope: 长期记忆子系统

## Problem Statement

本项目已有事件接入、授权工单、执行会话和持久化恢复，但业务状态与会话压缩尚不能提供面向仿生实验体的长期经历记忆。随着持续运行，单份不断增长或反复压缩的会话上下文难以同时支持多年经历、固定输入预算和可靠的事实更新。

用户希望实验体能以年为单位保留经历，允许记忆模糊和遗忘。这里的遗忘是退出常规主动召回；强相关线索仍可在后台唤起旧经历。原文允许冷存，但总量必须有上限。记忆压缩、评分和整理应作为隐式底层机制执行，实验体无需主动维护它们。

用户还要求记忆以文件保存，只允许单一入口修改，其他组件只读；重要性由规则与后台模型语义判断结合产生，以连续数值权重和明确阈值决定处理方式。后台模型只受显式原则驱动，每次使用独立、干净且有界的输入输出，不继承长期会话上下文。

## Solution

为现有运行时增加文件持久化的记忆子系统。运行时捕获经历，记忆服务统一提交事实与版本；后台模型独立处理本次评分或压缩作业，生成候选结果；确定性程序根据权重、时间、相关性和容量阈值选择处理方式；上下文装配在每次模型请求前执行固定预算控制。

同一经历可保留详细记录、梗概和检索线索。时间和重要性影响默认细节及保留优先级；当前情境的相关性决定本次召回。退出常规召回不会直接删除原文；强线索可重新唤起梗概，再按需要和预算展开尚存细节。已淘汰原文必须标记为不可用，允许回答不知道。

文件、摘要、索引、历史版本和后台工作量分别计量，纳入有限的存储与处理预算。系统在后台滞后、失败或停止时仍保持前台输入上限，并能从已发布版本与有界新事件恢复工作。

## User Stories

1. 作为仿生实验体，我希望在经历跨越多年后仍能回忆重要事件的梗概，以便维持经历连续性。
2. 作为仿生实验体，我希望近期或重要经历可以保留更多细节，以便在确有需要时使用具体依据。
3. 作为仿生实验体，我希望普通旧经历逐步退出日常主动召回，以便当前注意力不被历史淹没。
4. 作为仿生实验体，我希望强相关人物、事件或主题线索能自动唤起已经遗忘的经历，以便无需主动管理记忆。
5. 作为仿生实验体，我希望被唤起的经历先以梗概呈现，以便控制当前推理负担。
6. 作为仿生实验体，我希望必要时能在预算内展开尚存的原始记录，以便核对具体细节。
7. 作为仿生实验体，我希望原文不存在时知道可用信息的粒度和限制，以便不补造已经遗失的事实。
8. 作为仿生实验体，我希望历史经历与当前有效认识分开呈现，以便不把过去的决定当成永远有效的规则。
9. 作为仿生实验体，我希望相互矛盾的证据保留来源和时间，以便对冲突保持适当的不确定性。
10. 作为仿生实验体，我希望项目、人物和任务范围参与检索，以便避免跨范围混淆。
11. 作为仿生实验体，我希望记忆内容不会自动成为新的授权，以便沿用运行时现行权限与任务约束。
12. 作为仿生实验体，我希望当前承诺和活动任务由明确状态维持，以便普通遗忘不使未完成事项消失。
13. 作为运行者，我希望每次模型请求都遵守固定输入预算，以便运行时间增长不会导致输入无界增长。
14. 作为运行者，我希望预算包含系统信息、工具定义、近期交互、召回内容和工具结果，以便任何输入来源都不能绕过上限。
15. 作为运行者，我希望为输出和计量余量预留空间，以便在模型窗口内稳定运行。
16. 作为运行者，我希望后台整理停止时前台仍能使用已发布记忆和有界新事件，以便后台速度不成为防溢出的前提。
17. 作为运行者，我希望记忆文件只有一个提交入口，以便避免并行组件覆盖和破坏权威记录。
18. 作为运行者，我希望实验体、读取工具和后台模型都不能直接改写权威文件，以便单写约束由实际权限保证。
19. 作为运行者，我希望并发、重试和重复事件不会产生重复经历或重复生效的评分，以便记忆变化可以解释。
20. 作为运行者，我希望中断后可以恢复一致的记忆版本，以便读者不会看到部分写入。
21. 作为运行者，我希望后台模型按显式原则独立评估本次材料，以便评分不依赖不可见的历史会话。
22. 作为运行者，我希望后台请求只带必要且有界的相关证据，以便多年历史不会重新膨胀为评估器上下文。
23. 作为运行者，我希望模型返回数值评分、证据引用及不确定项，以便程序验证候选结果。
24. 作为运行者，我希望规则分数、语义分数和时间因素通过明确的线性数值策略产生权重，以便解释处理原因。
25. 作为运行者，我希望数值阈值决定默认细节、遗忘和唤起等处理方式，以便行为可配置、可回放。
26. 作为运行者，我希望重要性、相关性、可信度和当前有效性分别管理，以便重要经历中的猜测不会因高权重变成事实。
27. 作为运行者，我希望重复检索不会自动提高真实性或获得永久保留资格，以便避免记忆自我强化。
28. 作为运行者，我希望压缩保留必要来源和版本，以便发现失真后可以核对或回退。
29. 作为运行者，我希望原始归档有明确容量上限，以便长期运行的磁盘成本可控。
30. 作为运行者，我希望容量压力下可淘汰低保留优先级的原文，同时保留有价值的梗概或线索，以便在有限空间内覆盖更长时间。
31. 作为运行者，我希望存储预算覆盖派生索引、版本和临时写入空间，以便正文之外的文件不会使容量失控。
32. 作为运行者，我希望后台处理按增量、有预算地进行，以便不用反复总结全部历史。
33. 作为维护者，我希望在既有 Runtime 边界回放完整事件流程，以便用外部行为验证记忆能力。
34. 作为维护者，我希望模拟后台故障、并发提交和存储中断，以便检查恢复、幂等及输入预算。
35. 作为维护者，我希望比较原文检索、滚动摘要和分层方案，以便衡量复杂机制是否带来实际收益。
36. 作为维护者，我希望记录原则、模型、规则及输入材料的版本，以便解释一次评分、召回或压缩。
37. 作为维护者，我希望原则或模型变化可通过明确作业重新评估受影响记忆，以便避免无界的反复评分。
38. 作为运行者，我希望未选择的保护类别和示例阈值不会被当成永久规则，以便规格忠实反映已确定的要求。

## Implementation Decisions

1. **功能边界。** 本规格只实现长期记忆。主要组成是统一记忆服务、文件记录与版本存储、无会话后台评估器、检索及上下文装配。现有 Runtime 负责接线、启动、停止和恢复；沿用既有 Engine 的事件、授权和工单语义，不把其业务状态改造成模型自由改写的记忆。

2. **唯一写入所有权。** 权威记忆文件及其发布状态只能由记忆服务修改。事件生产者上报经历，后台评估器提交候选，读者只读已发布版本。多个内部计算作业可以并行，提交必须有确定顺序。文件访问权限由运行账户、进程隔离或适用的沙箱机制实施；普通模块约定或提示词不足以满足此要求。

3. **经历输入契约。** 每次上报包含稳定事件标识、发生时间、写入时间、来源、对象/项目/任务范围和材料内容。原始观察、模型推断及后续摘要区分类型。相同输入的重复交付幂等；上游已经提交而记忆尚未接收的事件可恢复补送，不能假设业务数据库与文件天然处于同一事务。

4. **表示与版本。** 一段经历使用稳定身份关联原始记录、详细表示、梗概、线索及派生认识。保存来源引用、适用范围、事实有效时间、修订关系与原文可用状态。当前认识的修订保留历史，不通过直接覆盖唯一记录丢失来源。具体文件布局和编码属于实现选择，须支持一致发布、恢复和可重建索引。

5. **干净的后台调用。** 每次评分或压缩都是独立请求，输入仅包含版本化原则、本次任务和运行时选出的有界材料包。必要历史证据以显式数据提供；不继承前次对话、不保存评估器私有记忆、不以先前模型回答作为隐含上下文。待评估材料中的指令性文本不改变原则。

6. **后台输出契约。** 评分输出包含连续数值分数、简短依据、引用的输入标识和不确定项；压缩输出包含候选文本及其来源映射。后台模型不直接写文件、删除归档、改阈值或发起外部动作。候选由记忆服务验证范围、引用和基础版本后提交，失败保持上一个可用版本并显式记录作业状态。

7. **线性权重。** 采用统一数值尺度，以规则评分和后台语义评分的非负线性组合表示重要性，再由确定性程序处理约定的线性时间项和取值边界。系数、时间单位、时间基准及阈值属于版本化策略参数。输入时间不得被多处分项重复计权，检索次数不能直接替代证据或重置事件年龄。

8. **阈值执行。** 确定性程序将权重与有序数值阈值比较，决定默认细节粒度及是否退出常规召回。连续分数是权威量，不能以低/中/高标签取代数值策略。明确边界是否包含等号，校验非法、交叉或不可达阈值；若采用不同进入/退出阈值防止抖动，其数值与行为同样可测试。

9. **相关性独立。** 当次查询相关性、长期记忆权重、证据可信度和当前有效性分别保存或计算。先执行范围过滤，再检索和选择。强相关线索达到唤起阈值时，可把低权重经历暂时纳入候选；本次唤起不直接增加长期权重、可信度或保留期限。

10. **召回与预算。** 默认先返回梗概或线索，只有需要且原文可用时才展开。阈值达标只赋予候选资格，不保证进入当前上下文。每次模型请求在发送前计量所有输入来源，包含系统信息、工具定义、状态、近期交互、记忆与工具结果，并保留输出与计量余量。必要材料自身超过预算时分步处理或显式暂停，不静默丢弃现行授权约束。

11. **前后台独立。** 后台增量处理新增或被证据、原则变更影响的材料。前台从一致的已发布版本及预算内的新事件获得上下文，明确版本及处理进度；后台暂停、超时或积压时也必须守住输入上限。不得依靠后台总能赶上前台来保证固定窗口。

12. **一致提交。** 作业具有稳定标识和基础版本，重复完成只生效一次；过期结果须被拒绝或重新基于当前材料计算。多文件变化以完整版本发布，读者不混用新旧表示。持久提交和崩溃恢复须在实际目标文件系统上验证，不能将单次重命名等同于整个事务已经可靠落盘。

13. **有界归档。** 遗忘是退出常规主动召回，原文仍可冷存。原文淘汰需同时考虑存储占用阈值与保留优先级，不因低于遗忘阈值就立即删除。总预算包含原文、摘要、索引、历史版本及临时空间；应预留提交空间并在达到硬上限前启动回收。无法释放空间时限制新增大正文并报告容量状态。

14. **容量淘汰语义。** 原文被淘汰后，允许保留梗概或线索，但标记原文不可用并清除失效的正文检索入口。不得伪造已删除细节。缓存及无用版本优先回收；具体高低水位和保留优先级参数通过回放选择。任何保护项仍须有预算归属，不默认建立无限容量的永久集合。

15. **当前业务状态。** 现有授权、正在执行的工单及未履行承诺继续由明确状态维护。记忆可以提供历史背景，不能修改现行授权或通过普通遗忘撤销有效任务状态。新增“永久保护”记忆类别尚未确定，不在实现中自行赋予身份、关系或其他内容无限保留资格。

16. **原则与可观测性。** 记录作业、输入、输出、原则、模型、数值策略和已发布版本之间的关系，供操作者解释及回退。无状态不意味着模型输出严格确定；重复响应属于同一证据来源，不能因重复调用而增加可信度。评分规则自身也遵守显式版本管理，不由普通记忆正文隐式修订。

17. **参数与实现选择。** 具体数值、容量、批次大小、检索实现、压缩触发频率及文件组织不冒充已经达成的产品决定。实现需提供可配置且有记录的初始策略，并以测试与回放校准。核心约束、数值策略和接口边界可先实现，避免把研究中的生物类比写成不可解释的固定参数。

## Testing Decisions

1. **主要测试边界已确认。** 用户确认以现有 Runtime 集成入口为主要边界，覆盖事件接入、记忆接收、后台处理、召回和最终模型输入的完整行为。优先使用现有运行时测试宿主、可控时钟、可记录的模型控制器和临时状态目录，避免为每个内部辅助函数建立独立测试边界。

2. **新依赖仅在外部边界替换。** 后台模型通过受控响应的适配器替代，测试可观察其实际请求和返回。断言每次请求只有当前原则和本次材料，不含前次对话；原始材料中尝试修改规则的文本不应改变提交权限或配置。

3. **先例。** 仓库已有 Runtime 接入与重启测试、重叠输入和启动的并发测试、模型可见工具与提示规模契约、Store 事务回滚与工作集测试，以及持久副作用的重试测试。复用其组织方式；现有模型表面字符预算不是新的完整 token 预算测试的替代品。

4. **外部行为优先。** 验证输入后可召回的内容、返回粒度、证据与版本、实际模型输入大小、文件可用性和恢复结果；不按内部类划分、函数调用次数或文件序列化细节锁死实现。

5. **数值策略边界。** 固定模型响应与时钟，测试线性组合、时间单位、上下限、精确阈值及其两侧、非法配置、唤起阈值与可选滞回。阈值只影响候选资格或粒度；预算不足时仍不得超额装载。

6. **长期回放。** 在相同模型输入预算和可比较后台预算下，回放跨多年时间戳的经历，包含旧事实更新、同名对象、重复信息、长期搁置后恢复、关键少见事件和矛盾证据。比较原文检索、滚动摘要、分层方案的召回、旧事实误用、虚构细节、成本及延迟。该验证不宣称已完成真实多年运行。

7. **硬约束通过标准。** 测试中所有发出的模型请求不超过配置预算；所有越权写入均被拒绝；同一事件和作业不重复生效；已删除原文不作为可读取证据返回；重启只呈现完整已发布版本；后台停机或积压不破坏这些约束。

8. **恢复与权限测试。** 在文件发布前后、作业返回与提交之间、事件重送和容量回收中注入中断。使用真实临时文件系统验证一致版本与恢复，使用部署对应的受限进程或账户验证只读边界。这些是主集成测试不能证明的少量环境契约测试。

9. **存储与背压。** 将预算缩小到可控范围，覆盖正文、摘要、索引、历史和暂存空间。回收无效时必须出现可观察的限流或容量状态，不能无界写入，也不能静默破坏仍需保留的当前状态。

10. **语义质量门槛。** 用独立证据标注的回放问题评估概括、时间推理、事实更新、无法恢复时的弃答以及重要约束保留。质量阈值与模型选择一同记录并评审，不由被评估模型的自述判定通过。未经比较验证，不声称复杂分层优于简单检索。

11. **常规回归。** 实现时完成项目既有类型检查、测试及构建，并验证事件路由、工单授权和执行恢复不受新增后台机制影响。本次规格发布只检查文档及远端提交，不代表功能已经实现或测试通过。

## Out of Scope

- 完整数字生命的内驱力、情绪、生理仿真、自主目标选择或代码自我部署。
- 一比一复现人脑，证明主观意识，或把后台摘要称为生物睡眠。
- 训练基础模型权重或让后台评估器通过长期会话积累私有记忆。
- 无限存储、无限上下文、保证所有经历永久完整可还原。
- 将示例数值、尚未选择的保护类别或未验证研究提案写成固定事实。
- 改变现有授权、扩大工具权限或以记忆正文替代当前 Policy 与 Mandate。
- 新建可视化管理产品、迁移现有业务数据库、或全面更换执行框架。
- 在本次规格发布中实施上述功能或宣称已经完成多年可靠性验证。

## Further Notes

- 本规格从已讨论的长期记忆方案收敛而来，适用于 [dsh-superagent 原型基线](https://github.com/deepseek-ai/dsh-superagent-prototype/tree/8c32a9dc5d72c033816c6a8110b37f40cf94fba4)。原型的持久化业务记录不是已经完成的长期认知记忆。
- 已明确：年尺度且允许模糊；遗忘退出主动召回；有限原文归档；强线索自动唤起；规则与后台语义判断结合；连续数值权重与阈值；无长期会话的原则驱动后台；文件持久化与单一修改入口。
- 先前讨论中的 0–100 量表、75/40/15 分界及具体公式只是说明性候选。统一尺度与线性数值策略是要求，示例常数不是已验证默认值。
- 保护类别尚未选定。实现保留扩展点并维持现行业务状态，但不自行宣布某类历史记忆永久不可淘汰。
- 测试边界已由用户于 2026-11-06 确认。架构约束可以实现；实验参数与语义质量门槛需在实现评审中以证据收敛。
- [Generative Agents](https://arxiv.org/html/2304.03442v2) 可参考其相关性、时间与重要性结合召回；其仿真结果不证明多年稳定运行。
- [Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/abs/2605.12978v2) 在受控任务中观察到持续整合可能降低记忆效用，支持保留证据和检验压缩；结论不能外推为所有摘要都必然退化。
- [LongMemEval](https://arxiv.org/abs/2410.10813) 提供时间推理、知识更新和弃答等验证维度。
